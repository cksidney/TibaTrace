# TibaTrace System DPIA Gap Closure Register

**Assessment:** TibaTrace system/provider DPIA, version 0.3  
**Review date:** 17 October 2026  
**Status:** OPEN — the assessment remains not approved  
**Purpose:** Track the facts, controls, and accountable decisions needed to close the DPIA findings. This register is not a certificate, legal opinion, or approval.

## What this review closed

These items are closed at the document/source-review level only. They do not substitute for production evidence or accountable-owner approval.

| Item | Closure in this review | Boundary |
|---|---|---|
| DPIA scope | The assessment now covers TibaTrace as a system/provider. It does not ask each customer tenant to approve the provider's DPIA. | Each tenant still assesses its own controller purposes and lawful bases. |
| Processing description | The DPIA describes patients, practitioners, workforce, business records, the hosted architecture, attachments, logs, backups, exports and external trust boundaries. | Exact production providers, countries, integrations and volumes still require live-owner evidence. |
| Owner statements | The system owner's representations that TibaTrace operates within applicable law and uses a seven-year retention baseline are recorded. | “Within the law” does not identify each purpose, controller/processor role, lawful basis or health-data condition. Seven years does not establish start triggers, exceptions or purge behavior. |
| Source safeguards | Existing tenant/capability controls, identifier protection, attachment authorization/integrity/audit, production TLS settings, password throttling and fail-closed malware scanning are distinguished from runtime proof. New object writes now use AES-256-GCM; production requires a valid external versioned keyring, and an integrity-checked legacy-object migration command is available. | Source code and tests do not prove that the live deployment runs the reviewed revision, the keyring is provisioned, legacy objects are migrated, or external controls are configured. |
| Historical readiness material | The August 2026 DHA scorecard and evidence register are being corrected to show their age and limits, including removal of “certification ready” as a current status. | Only DHA can establish official certification or its applicability. |

## Safe execution order

1. Complete DPIA-01 through DPIA-05 to establish the accountable entity, processing boundary, release, scale and data flows.
2. Approve DPIA-06 before engineering implements irreversible deletion rules. Do not auto-delete health or financial records based on an unspecified seven-year trigger.
3. Close the security and recovery evidence in DPIA-08 through DPIA-11 on the exact production release. Implement a missing control before recording it as complete.
4. Close DHA applicability/certification in DPIA-12 before any legally restricted clinical use or exchange.
5. Complete consultation and residual-risk approval in DPIA-13 after mitigations are evidenced.

The assessment can be submitted for review after these items have owners and evidence; only the accountable system owner and required reviewers can change its approval decision. Do not change the status to approved solely because this register or a code test is complete.
